# Contributing

## How the repo fits together

`design-system/tokens.json` is the single source for colours, spacing and
radii. `tools/generate.py` turns it into the theme files under `packages/`.
Never edit a file that starts with "Generated by tools/generate.py"; change
the token or the generator and run it again.

Each folder in `packages/` with a `debian/` directory is one Debian package.
They are all `Architecture: all` and nothing compiles.

## Change a theme and test it without rebuilding the ISO

1. Edit the token or the generator in `tools/gen_*.py`.
2. `python3 tools/generate.py`
3. `scripts/build-debs.sh <package-dir>` — for example `scripts/build-debs.sh kvantum-theme`.
4. Copy the `.deb` from `out/debs/` into a Debian 13 + Plasma VM and `sudo apt install ./the.deb`.
5. Apply it with the command in `docs/TESTING.md` and check it against the board in `design-system/boards/`.

Only rebuild the ISO (`scripts/build-iso.sh`) when you change `live-build/`
or want to check the installed system end to end.

## Design rules that reviews check

- Monochrome. Selection and "on" states invert to the text colour.
- Red (`accent`) is only a live marker or an error. See the Colour section of `design-system/README.md`.
- No shadows, blur, gradients or translucency. Motion is fade only.
- Every value comes from a token. If you need a new one, add it to the design system first.

## Pull requests

- One package or one concern per pull request.
- Say how you tested it: which VM, which apps, dark and light.
- Include a before and after screenshot for anything visible.
- CI builds every package; it must pass.

## Reporting bugs

Use the "Theme bug" template for something that looks wrong, and "ISO build
failure" when the image does not build or boot.
